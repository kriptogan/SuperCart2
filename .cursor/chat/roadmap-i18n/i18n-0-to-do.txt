## 📝 **NOTES**

### **Android i18n Best Practices:**
1. **Never use `left` and `right` in layouts** → Use `start` and `end`
2. **Test with "Force RTL layout" in Developer Options**
3. **Use `layoutDirection` property to force direction programmatically**
4. **Avoid hardcoded strings** → Always use `R.string.xxx`
5. **Consider plurals** → Use `<plurals>` resource for countable items

### **RTL Considerations:**
- Text alignment: `textAlignment="viewStart"` (not "left")
- Padding: `paddingStart`/`paddingEnd` (not "Left"/"Right")
- Icons: Some need mirroring (arrows), some don't (logos)
- Images: Use `autoMirrored="true"` for directional icons

### **Translation Sources:**
- Initial translations: Use Google Translate / DeepL
- Professional translations: Consider for production
- Community translations: Can crowdsource if app grows

## ⚠️ **POTENTIAL CHALLENGES**

### **Challenge 1: Forcing Language Direction**
- **Issue:** Android defaults to device OS language/direction
- **Solution:** Override `attachBaseContext()` in MainActivity to force locale

### **Challenge 2: RTL Layout Issues**
- **Issue:** Some layouts may break in RTL
- **Solution:** Use `start`/`end` instead of `left`/`right`, test thoroughly

### **Challenge 3: Dynamic Language Switching**
- **Issue:** Compose may not recompose after locale change
- **Solution:** Store language in state, trigger recomposition

### **Challenge 4: Translation Quality**
- **Issue:** Auto-translated strings may be awkward
- **Solution:** Start with auto-translate, refine over time

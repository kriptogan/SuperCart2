Store Model Structure:
---
package com.example.supercart2.models

import java.util.UUID
import java.time.LocalDateTime

data class Store(
    val uuid: String = UUID.randomUUID().toString(),
    val name: String,
    val viewOrder: Int = 0,
    val lastUpdate: LocalDateTime = LocalDateTime.now(),
    val deleted: Boolean = false
)
---

Grocery Model Update:
---
Add this field to existing Grocery data class:
val storeIds: List<String> = emptyList()

This allows groceries to be linked to multiple stores.
Defaults to empty list for backward compatibility.
---


📐 DESIGN DECISIONS
═══════════════════════════════════════════════════════════════════
1. Store Model:
   - Similar structure to Category/SubCategory models
   - viewOrder for custom ordering (like categories)
   - No protected field (all stores can be deleted)
   - deleted field for soft deletion (Firebase sync pattern)

2. Grocery-Store Relationship:
   - Using List<String> storeIds (denormalized)
   - Alternative considered: Separate junction table
   - Chosen for simplicity and consistency with existing patterns

3. Default Values:
   - Empty storeIds list = not linked to any store
   - Will appear in "Not Linked to Any Store" section

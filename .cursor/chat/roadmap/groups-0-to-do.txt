⚠️ IMPORTANT NOTES
═══════════════════════════════════════════════════════════════════
- Serial code is a random UUID (e.g., abc-123-def-456)
- One group per user at a time
- No owner role - all members equal
- Create group = upload current data
- Join group = download and overwrite local data
- Leave group = clear code, keep local data
- Conflict resolution: latest lastUpdate wins
- Anyone with code can join (no verification)
- Serial code MANDATORY for all cloud operations
- Images NOT synced (local only)
- Hidden stores and view mode NOT synced (per-user)
- Existing cloud data will be deleted before implementation


📐 DESIGN DECISIONS
═══════════════════════════════════════════════════════════════════
1. Group Code Format: Random UUID (standard format)
2. Storage: DataStore for local, Firestore path: /groups/{code}/
3. Conflict Resolution: lastUpdate timestamp (latest wins)
4. Access Control: Anyone with UUID can join
5. Leave Behavior: Clear code, preserve local data
6. Orphaned Groups: Data persists in cloud even if all leave
7. UI Location: New "Family Group" menu in burger menu
8. No Member Visibility: Users cannot see group members
9. No Activity Log: No "last edited" information
10. Images: Local only (not synced for now)
